이용약관 개정 안내

2026년 11월 3일에 알린 개정 계약을 2026년 11월 11일에 보완해, 그 뒤 더해진 기능에 관한 내용을 넣었습니다. 이 페이지의 개정 계약은 그대로 2027년 1월 1일부터 시행합니다.

  • Windows용 Branch에는 2026년 11월 3일에 알린 내용이 설치하거나 사용한 때부터 그대로 적용되고, 11월 11일에 더한 내용은 2027년 1월 1일부터 적용됩니다.
  • macOS용 Branch에는 시행일 전까지 2026년 10월 20일 계약이 그대로 적용됩니다.

2026년 11월 11일에 더한 주요 내용

  • GitHub·GitLab 계정 연결: 설정 → 계정 및 연동에서 개인 액세스 토큰으로 계정을 연결한 경우에만, 원격 주소가 그 서비스를 가리키는 레포의 커밋 기록이 열려 있는 동안 요청하지 않아도 현재 로컬 브랜치의 풀 리퀘스트·머지 리퀘스트와 커밋의 CI 결과를 그 서비스에서 주기적으로 읽어 옵니다. 이 요청에는 액세스 토큰, 그 서비스에서의 레포 경로, 로컬 브랜치 이름과 커밋 ID가 담깁니다. 설정 → 계정 및 연동을 열면 계정의 프로필 사진도 불러옵니다. 토큰은 macOS에서는 로그인 키체인, Windows에서는 Windows 자격 증명 관리자에 저장해 그 서비스에만 보내고, 연결을 해제하면 조회를 멈추고 토큰을 지웁니다. 앱을 삭제해도 토큰은 지워지지 않으니, 먼저 연결을 해제하거나 macOS의 키체인 접근, Windows의 자격 증명 관리자에서 지우십시오. (제7조 제2항~제5항, 제10조 제3항)
  • Drone CI 연결: 설정 → 계정 및 연동에서 Drone 서버의 주소와 액세스 토큰을 입력해 연결한 경우에만, 그 서버 주소의 /api로만 요청합니다. "Drone CI" 창이 열려 있으면 끝나지 않은 빌드가 있는 동안 10초마다, 그리고 현재 브랜치나 원격의 이름·주소가 바뀔 때마다 빌드를 다시 읽고, 빌드는 이용자가 확인한 뒤에만 실행하거나 다시 실행합니다. 토큰은 계정 연결의 토큰과 같은 방식으로 저장하고 지우며 그 서버에만 보냅니다. http:// 주소에서는 토큰과 응답이 암호화되지 않은 채 오가므로 가능하면 https:// 주소를 쓰십시오. (제7조 제2항~제5항, 제10조 제3항)
  • 외부 터미널 선택: 설정 → 외부 앱의 외부 터미널에서 고른 앱(고르지 않으면 macOS에서는 터미널, Windows에서는 Windows 터미널)으로 레포를 열고, 그 선택을 설정에 저장합니다. (제7조 제4항 제1호, 제5항)
  • 자동 Bisect 테스트와 판정 수정: 이용자가 고른 테스트 프로그램을 검토하고 실행을 확인하면, 테스트할 커밋을 체크아웃한 작업 폴더에서 그 프로그램을 이용자의 권한으로 실행합니다. 그 프로그램이 하는 일은 앱이 정하거나 제한하지 않습니다. 테스트 기록(최근 100회까지)은 앱에서 Bisect 세션을 끝내면 지우지만, 판정을 고칠 때 남기는 수정 전후의 Bisect 기록은 자동으로 지우지 않고 앱에서 지울 수도 없으니 필요 없으면 직접 지우십시오. (제7조 제4항 제12호·제13호, 제5항)
  • 워크트리 등록 보관함: 폴더가 없어진 워크트리의 등록을 정리하면, Git이 그 워크트리에 대해 기록한 정보(현재 브랜치, 인덱스, 작성자 이름·이메일과 커밋 메시지가 담긴 reflog 등)와 그 워크트리의 버린 변경의 복구본, Bisect 기록을 지우지 않고 레포의 공통 Git 폴더 안 branch/worktree-archives/로 옮겨 보관합니다(최대 32개). 등록을 되돌리거나 직접 지울 때까지 기한 없이 남으며, 앱에는 보관함을 지우는 기능이 없습니다. (제7조 제4항 제10호·제14호)
  • Git LFS 잠금과 이력 변환: Git LFS 잠금의 조회·설정·해제는 이용자가 요청한 경우에만 원격에 연결해 처리합니다. Git LFS 이력을 변환한 새 브랜치를 만들 때에는 원본 브랜치가 가리키는 커밋을 복구 지점으로 남깁니다. (제7조 제3항, 제4항 제5호)
  • 커밋 메시지 템플릿: 이용자가 고른 템플릿 파일의 경로는 저장한 경우에만 Git 설정의 commit.template에 기록하고, 미리보기를 위해 그 파일의 내용을 기기 안에서 읽습니다. (제7조 제4항 제3호)
  • 사용자 정의 작업: 설정 → 사용자 정의 작업에서 등록한 작업(최대 50개)은 기기에 저장하고 설정 백업에도 넣지만, 백업을 가져와도 실행하지는 않습니다. 레포·브랜치·파일 메뉴에서 작업을 고르면 실행할 프로그램, 인자와 작업 폴더를 보여 주고, 실행할 때마다 확인을 받은 뒤에만 이용자의 권한으로 실행합니다(최대 30분). 결과는 작업 기록에 남으며, 그 프로그램이 하는 일은 앱이 정하거나 제한하지 않습니다. (제7조 제4항 제8호·제15호, 제5항)
  • 저장한 커밋 검색: 커밋 기록의 "저장한 커밋 검색" 창에서 저장한 검색 조건(레포마다 최대 30개)을 기기에 저장하며, 검색 결과는 저장하지 않습니다. 그 창에서 지울 때까지 기한 없이 남고(레포를 닫거나 목록에서 빼도 남습니다), 설정 백업에 포함됩니다. (제7조 제4항 제16호)
  • 실행 중의 업데이트 확인: 설정 → 업데이트의 "업데이트 자동 확인"이 켜져 있으면(기본값) 시작할 때가 아니라 시작하고 30초 뒤에, 그리고 실행되는 동안 24시간마다 새 버전이 있는지 확인합니다. (제6조 제2항 제1호)
  • 새 기능의 임시 폴더: Git LFS 이력 변환, 서브모듈 주소 동기화, 체리픽·되돌리기·리베이스·대화형 리베이스 창의 충돌 미리 확인, 커밋 패치 가져오기와 커밋 메모 저장·삭제에 필요한 레포 내용과 파일을 운영체제의 임시 폴더에 두었다가 작업이 끝나면 지웁니다. 작업 중에 앱이 종료되면 그 폴더에 남을 수 있습니다. (제7조 제5항)
  • 그 밖에: 커밋 패치를 가져오기 전에도 복구 지점을 남기고, 이용자가 확인하고 바꾼 원격, 업스트림 브랜치, 서브모듈 주소 같은 설정은 그 레포의 Git 설정에 기록합니다. 서브모듈을 갱신할 때에는 레포의 Git 설정에 있는 갱신 방식 대신 기록된 커밋을 체크아웃하며, 서브모듈 주소를 동기화할 때 .gitmodules의 주소에 자격 증명이 들어 있으면 그 주소가 레포의 Git 설정에 기록될 수 있습니다. (제7조 제3항, 제4항 제3호·제5호)

이 가운데 GitHub·GitLab 계정 연결, Drone CI 연결, 사용자 정의 작업, 저장한 커밋 검색과 실행 중의 업데이트 확인은 시행일 전에는 제공하지 않습니다.

2026년 11월 3일에 알린 주요 변경 내용

  • Windows 지원: 계약이 macOS용과 Windows용 Branch에 함께 적용됩니다. Windows에서 정보가 저장되는 위치, 앱에 포함된 Git(MinGit, Git LFS, Git Credential Manager)과 로그인 정보 저장, Microsoft Edge WebView2 런타임처럼 Windows에서 다른 점을 적었습니다. (제1조, 제7조, 제10조)
  • 자동 페치: 설정 → Git에서 주기를 고른 경우에만(기본값은 사용 안 함), 앱이 실행되는 동안 그 주기마다 현재 작업공간에 열린 레포를 페치합니다. 레포마다 끌 수 있고, 이미 저장된 로그인 정보만 쓰며, 작업 중인 파일과 로컬 브랜치는 바꾸지 않습니다. (제7조 제2항·제3항)
  • 기기에 저장되는 정보: 작업 기록, 충돌 해결 초안, 버린 변경의 복구본, 설정 스냅샷, 연습용 레포 등 기기에 저장하는 정보와 그 저장 위치, 보관 기준을 적었습니다. 모두 기기에만 저장되며 회사로 보내지 않습니다. (제7조 제4항)
  • 앱이 기록하는 Git 설정: 작성자 이름과 이메일, 서명 설정, 풀 방식은 앱에서 저장한 경우에만 Git 설정에 기록합니다. 레포에서 Git LFS를 설정하면 Git LFS 설정을 기록하고 pre-push 훅이 없으면 만들며, 추적 규칙을 바꾸면 .gitattributes를 고칩니다. (제7조 제4항 제3호)
  • 서명 확인: 서명된 커밋의 상세가 보이면 Git 설정에 지정된 서명 프로그램(따로 정하지 않으면 gpg 또는 ssh-keygen)이 기기에서 서명을 확인합니다. 레포를 열 때 현재 커밋이 자동으로 선택되므로 커밋을 고르지 않아도 확인이 이루어질 수 있고, GnuPG 설정에 따라 GnuPG가 공개 키를 찾으려고 키 서버에 연결할 수 있습니다. (제7조 제3항)
  • 저장된 로그인 정보: 자격 증명 도우미는 저장된 로그인 정보를 갱신하거나 확인할 때 원격 서비스의 로그인·인증 주소에 연결할 수 있고, 원격 서비스가 그 로그인 정보를 거부하면 지울 수 있습니다. 자동 페치 중에도 마찬가지이며, 지워지는 항목은 다른 Git 앱과 함께 쓰는 것일 수 있습니다. (제7조 제3항)
  • 그 밖에: 원격 작업 목록에 Git LFS 내용 내려받기를 더하고, 외부 비교·병합 도구에 넘기는 임시 사본과 그 삭제를 적었습니다. (제7조 제3항·제5항)

회사가 소프트웨어로 정보를 수집하지 않는다는 점과 베타 기간의 무료 이용은 바뀌지 않습니다. 시행일 이후에도 계속 사용하면 개정에 동의한 것으로 보며, 동의하지 않으면 사용을 중단하고 계약을 해지할 수 있습니다(제14조 제3항).

제1조 (목적 및 동의)

  1. 이 계약은 Paldyn(팔딘, 이하 "회사" 또는 "PALDYN")이 제공하는 데스크톱 Git 클라이언트 "Branch"의 실행 파일(Windows용 설치 프로그램을 포함합니다), 업데이트 및 함께 제공되는 문서(이하 통칭하여 "소프트웨어")를 이용하는 조건을 정합니다. 소프트웨어는 macOS용과 Windows용으로 제공되며 이 계약은 둘 모두에 적용됩니다. 운영체제에 따라 다른 내용은 해당 조항에 함께 적으며, 지원하는 운영체제와 그 버전은 회사 웹사이트(paldyn.com/branch)에서 안내합니다.
  2. 이용자는 소프트웨어를 설치하거나 사용함으로써 이 계약에 동의합니다. 이 계약에 동의하지 않는 경우 소프트웨어를 설치하거나 사용하지 마십시오.
  3. 이용자가 법인 등 단체를 위하여 소프트웨어를 사용하는 경우, 이용자는 그 단체를 대신하여 이 계약에 동의할 권한이 있음을 확인합니다.

제2조 (정의)

  1. "베타 기간"이란 회사가 소프트웨어의 정식 출시 또는 베타 종료를 회사 웹사이트(paldyn.com/branch) 게시와 업데이트 릴리즈 노트로 알리기 전까지의 기간을 말합니다.
  2. "유료 플랜"이란 구독, 일회성 구매, 유료 기능 등 회사가 대가를 받고 제공하는 소프트웨어 이용 형태를 말합니다.
  3. "업데이트"란 회사가 제공하는 소프트웨어의 수정판, 새 버전 또는 패치를 말합니다.
  4. "제3자 구성요소"란 소프트웨어에 포함된 오픈소스 소프트웨어, 글꼴, 아이콘 등 제3자가 권리를 가진 구성요소를 말합니다.
  5. "피드백"이란 이용자가 소프트웨어에 관하여 회사에 제공하는 의견, 제안, 오류 보고 등을 말합니다.

제3조 (베타 라이선스의 부여)

  1. 회사는 이 계약의 조건에 따라 베타 기간 동안 이용자에게 소프트웨어를 무상으로 사용할 수 있는 비독점적이고, 양도 및 재허락이 불가능하며, 철회할 수 있는 라이선스를 부여합니다.
  2. 이용자는 개인적 목적과 상업적 목적(업무용 저장소 관리를 포함합니다) 모두를 위하여 소프트웨어를 사용할 수 있습니다.

(Git 원격 작업) 저장소 복제(clone), 페치(fetch), 풀(pull), 푸시(push), 원격 참조 조회(설정 → Git의 연결 점검 포함), 서브모듈 추가와 갱신, Git LFS 내용 내려받기, Git LFS 잠금의 조회·설정·해제 등 Git 원격 작업은 이 항의 끝에 적힌 자동 페치를 제외하고는 이용자가 요청한 경우에만 수행됩니다. 소프트웨어는 Git 프로그램(소프트웨어에 포함된 Git, 또는 이용자가 설정에서 선택하거나 포함된 Git을 실행할 수 없는 경우 이용자의 컴퓨터에 설치된 Git)을 실행하여 이 작업을 처리하며, 이용자가 입력하거나 선택한, 또는 저장소에 설정된 원격 주소(서브모듈 주소를 포함합니다)에만 연결합니다. 허용되는 전송 방식은 file, https, http, ssh, git입니다. 인증은 이용자의 Git 설정, SSH 키와 자격 증명 도우미가 처리하며, 소프트웨어 자체는 제2항의 끝에 적힌 Git 서비스 계정과 Drone 서버의 액세스 토큰 외에는 비밀번호나 토큰 등 자격 증명을 저장하지 않습니다. 소프트웨어는 그 액세스 토큰을 macOS에서는 이용자 컴퓨터의 로그인 키체인(서비스 이름 com.paldyn.branch.hosting, 계정이나 Drone 연결마다 하나의 항목이며, Drone 서버의 토큰은 계정 이름이 drone:으로 시작하는 항목에 둡니다)에, Windows에서는 Windows 자격 증명 관리자(이름이 com.paldyn.branch.hosting:으로 시작하는 일반 자격 증명으로, Drone 서버의 토큰은 이름이 com.paldyn.branch.hosting:drone:으로 시작하는 것에 두며, 이 컴퓨터에만 보관)에 저장하고 그곳에서 읽어 오며, Git 서비스 계정의 토큰은 해당 Git 서비스에만, Drone 서버의 토큰은 이용자가 입력한 Drone 서버 주소에만 보냅니다. 이용자가 연결한 계정에서 고른 저장소를 복제하거나 그 복제의 연결을 점검할 때에는 소프트웨어가 그 액세스 토큰으로 직접 인증합니다. 이때 소프트웨어는 Git의 자격 증명 도우미(Windows의 Git Credential Manager를 포함합니다)를 쓰지 않고 로그인 창이나 입력 요청을 띄우지 않으며, 그 저장소의 주소에만 적용되는 인증 헤더를 Git의 실행 환경으로 넘깁니다. 이 실행 환경은 그 Git 작업이 실행하는 훅과 필터에도 전달됩니다. 포함된 Git을 사용하는 경우 macOS에서는 소프트웨어에 포함된 Git의 macOS 키체인 자격 증명 도우미가 기본으로 설정됩니다(이용자의 Git 설정으로 바꿀 수 있습니다). 이 도우미는 Apple의 Git에 포함된 도우미와 마찬가지로 Git이 인증에 성공한 HTTPS 자격 증명을 이용자 컴퓨터의 로그인 키체인에 저장하고 그곳에서 읽어 옵니다. Windows에서는 소프트웨어에 포함된 Git에 들어 있는 Git Credential Manager가 기본 자격 증명 도우미로 설정됩니다(이용자의 Git 설정으로 바꿀 수 있습니다). Git Credential Manager는 원격 작업(연결한 계정으로 하는 복제와 그 연결 점검은 제외합니다)에 HTTPS 인증이 필요할 때 저장해 둔 로그인 정보를 쓰고(필요하면 그 로그인 정보를 갱신하거나 확인합니다), 이용자가 요청한 원격 작업이면 기본 브라우저나 자체 창에서 해당 원격 서비스의 로그인을 진행하며, 이 과정에서 그 서비스가 로그인과 인증에 쓰는 주소(예: GitHub의 API 주소, Azure DevOps의 Microsoft 계정 로그인 주소)에도 연결할 수 있습니다. Git Credential Manager는 로그인 정보(토큰이나 비밀번호)를 이용자 컴퓨터의 Windows 자격 증명 관리자에 저장하고 그곳에서 읽어 오며, 이 저장 위치는 이용자의 컴퓨터에 설치된 Git for Windows의 Git Credential Manager와 같습니다. 어느 운영체제에서든 이 자격 증명은 회사에 전송되지 않습니다. 다만 이용자가 원격 주소에 자격 증명을 포함하여 입력하거나 .gitmodules의 서브모듈 주소에 자격 증명이 들어 있으면, Git이나 소프트웨어(서브모듈 주소를 동기화할 때)가 그 주소를 저장소 설정에 기록할 수 있습니다. 원격 서비스(예: GitHub, GitLab, Bitbucket, Azure DevOps)와 주고받는 정보에는 해당 서비스의 약관과 개인정보 처리방침이 적용됩니다. Git 훅, 부분 복제(partial clone) 저장소의 자동 객체 내려받기 등 이용자의 Git 설정이나 저장소 설정에 따른 Git의 동작은 그 설정대로 이루어집니다. 다만 소프트웨어가 서브모듈을 갱신할 때에는 저장소 설정의 갱신 방식(submodule.<이름>.update의 merge, rebase 또는 명령)을 따르지 않고 기록된 커밋을 체크아웃하며, 갱신 방식이 none인 서브모듈은 이용자가 그 서브모듈을 직접 골라 갱신할 때만 체크아웃합니다. 커밋과 태그의 서명 확인도 이에 해당합니다. 커밋 기록 화면에 서명된 커밋의 상세가 표시되거나 이용자가 태그의 서명 확인을 열면 소프트웨어는 Git을 통해 이용자의 Git 설정에 지정된 서명 프로그램(따로 지정하지 않으면 OpenPGP 서명은 GnuPG의 gpg, SSH 서명은 ssh-keygen)을 이용자의 기기에서 실행하여 서명을 확인합니다. 소프트웨어는 저장소를 열 때와 브랜치 전환 같은 작업 뒤에 현재 커밋을 자동으로 선택하므로, 이 확인은 이용자가 커밋을 고르지 않아도 이루어질 수 있습니다. 소프트웨어가 이 확인에 따로 통신을 더하지는 않지만, 이용자의 GnuPG 설정(예: auto-key-retrieve나 키 서버 설정)에 따라 GnuPG가 서명한 사람의 공개 키를 찾으려고 키 서버 등에 연결할 수 있습니다. 소프트웨어는 화면을 최신 상태로 유지하기 위해 주기적으로, 그리고 보고 있는 저장소의 폴더에서 변경을 감지하면 저장소 상태를 다시 읽지만, 이때 페치(fetch) 등 원격 저장소에 연결하는 Git 명령은 실행하지 않습니다. 다만 이용자가 설정 → Git의 "자동 페치"에서 주기를 고르면(기본값은 "사용 안 함"이며, 1분부터 60분 사이에서 고를 수 있습니다), 소프트웨어는 실행되고 있는 동안 이용자의 추가 요청 없이 그 주기마다 현재 작업 공간에 열려 있는 저장소 중 자동 페치를 끄지 않은 저장소를 한 번에 하나씩, 그 저장소에 설정된 모든 원격 저장소에서 페치(git fetch --all --prune)합니다(이하 "자동 페치"). 자동 페치는 그 저장소에 설정된 원격 주소(Git Credential Manager 등 자격 증명 도우미가 저장된 로그인 정보를 갱신하거나 확인할 때에는 그 원격 서비스가 로그인과 인증에 쓰는 주소를 포함합니다)에만 연결하고, 이미 저장되어 있는 자격 증명만 쓰며, 소프트웨어는 로그인 창이나 입력 요청을 띄우지 않습니다. 다만 macOS는 다른 Git이 키체인에 저장한 자격 증명을 포함된 Git이 처음 읽을 때 접근을 허용할지 물을 수 있고, 이용자가 직접 설정한 자격 증명 도우미나 SSH 에이전트는 그 설정에 따라 확인을 요청할 수 있습니다. 원격 서비스가 저장된 로그인 정보를 거부하면 Git의 동작에 따라 자격 증명 도우미가 그 로그인 정보를 지울 수 있고, 자동 페치 중에도 그렇습니다. 지워지는 항목은 다른 Git 앱도 함께 쓰는 것(macOS에서는 로그인 키체인, Windows에서는 Windows 자격 증명 관리자의 항목)일 수 있습니다. 새로 로그인해야 하는 원격 저장소는 자동으로 페치되지 않으며, 그 실패는 작업 기록에 남습니다. 자동 페치는 작업 중인 파일과 로컬 브랜치를 바꾸지 않고, 원격 추적 브랜치를 갱신하며(원격에서 삭제된 브랜치의 원격 추적 브랜치는 지웁니다), 가져온 커밋을 가리키는 태그를 더할 수 있습니다. 설정 → Git의 "자동 페치"를 "사용 안 함"으로 바꾸면 자동 페치는 멈추며, 같은 곳의 저장소 목록에서 선택을 해제한 저장소는 자동으로 페치되지 않습니다.

Git LFS 이력 변환을 미리 보거나 실행할 때에는 운영체제의 임시 폴더에 비공개 Git 저장소(이름이 branch-lfs-conversion-으로 시작하는 폴더)를 만들어 변환에 필요한 저장소 내용(내보내기에서는 Git LFS 내용의 사본을 포함하며 최대 2GiB)을 담고 작업이 끝나면 지우며, 서브모듈 주소 동기화를 준비하는 동안에는 관련 설정 파일의 사본을 운영체제의 임시 폴더에 잠시 둡니다. 체리픽, 되돌리기, 리베이스와 대화형 리베이스 창에서 충돌을 미리 확인할 때에는 운영체제의 임시 폴더에 비공개 Git 저장소(이름이 branch-conflict-preview-로 시작하는 폴더)를 만들어 저장소 인덱스와 속성·무시 규칙 파일의 사본, 미리 계산한 병합 결과(충돌한 파일의 내용을 포함합니다)를 담고, 확인이 끝나면(15초 제한을 넘거나 취소된 경우를 포함합니다) 지웁니다. 커밋 패치를 미리 보거나 가져올 때(멈춘 가져오기나 패치 방식의 리베이스(git rebase --apply)를 계속하거나 건너뛸 때를 포함합니다)에는 이름이 branch-mailbox-로 시작하는 폴더에 커밋 패치의 사본을, 커밋 메모를 저장하거나 지울 때에는 이름이 branch-commit-note-로 시작하는 폴더에 메모 목록을 담은 Git 인덱스 파일을 같은 임시 폴더에 두고, 그 작업이 끝나면 지웁니다. 이러한 작업 중에 소프트웨어가 종료되면 그 폴더에 남을 수 있습니다.
  6. 회사가 유료 플랜의 라이선스 확인 등을 위하여 이 조에 적힌 것과 다르게 정보를 처리하려는 경우, 시행 전에 이 계약을 변경하여 회사 웹사이트(paldyn.com/branch) 게시와 업데이트 릴리즈 노트로 알리고, 관련 법령상 필요한 경우 이용자의 동의를 받습니다.
