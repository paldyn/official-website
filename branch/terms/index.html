제1조 (목적 및 동의)

  1. 이 계약은 Paldyn(팔딘, 이하 "회사" 또는 "PALDYN")이 제공하는 데스크톱 Git 클라이언트 "Branch"의 실행 파일, 업데이트 및 함께 제공되는 문서(이하 통칭하여 "소프트웨어")를 이용하는 조건을 정합니다.
  2. 이용자는 소프트웨어를 설치하거나 사용함으로써 이 계약에 동의합니다. 이 계약에 동의하지 않는 경우 소프트웨어를 설치하거나 사용하지 마십시오.
  3. 이용자가 법인 등 단체를 위하여 소프트웨어를 사용하는 경우, 이용자는 그 단체를 대신하여 이 계약에 동의할 권한이 있음을 확인합니다.

제2조 (정의)

  1. "베타 기간"이란 회사가 소프트웨어의 정식 출시 또는 베타 종료를 회사 웹사이트(paldyn.com/branch) 게시와 업데이트 릴리즈 노트로 알리기 전까지의 기간을 말합니다.
  2. "유료 플랜"이란 구독, 일회성 구매, 유료 기능 등 회사가 대가를 받고 제공하는 소프트웨어 이용 형태를 말합니다.
  3. "업데이트"란 회사가 제공하는 소프트웨어의 수정판, 새 버전 또는 패치를 말합니다.
  4. "제3자 구성요소"란 소프트웨어에 포함된 오픈소스 소프트웨어, 글꼴, 아이콘 등 제3자가 권리를 가진 구성요소를 말합니다.
  5. "피드백"이란 이용자가 소프트웨어에 관하여 회사에 제공하는 의견, 제안, 오류 보고 등을 말합니다.

제3조 (베타 라이선스의 부여)

  1. 회사는 이 계약의 조건에 따라 베타 기간 동안 이용자에게 소프트웨어를 무상으로 사용할 수 있는 비독점적이고, 양도 및 재허락이 불가능하며, 철회할 수 있는 라이선스를 부여합니다.
  2. 이용자는 개인적 목적과 상업적 목적(업무용 저장소 관리를 포함합니다) 모두를 위하여 소프트웨어를 사용할 수 있습니다.
  3. 이 라이선스는 회사가 배포한 실행 파일 형태의 소프트웨어를 이용자가 소유하거나 정당하게 관리하는 기기에 설치하여 사용하는 것에 한정됩니다. 소스 코드에 대한 권리는 부여되지 않습니다.
  4. 이 계약에서 명시적으로 부여하지 않은 모든 권리는 회사에 유보됩니다.

제4조 (유료 플랜의 도입)

  1. 회사는 향후 유료 플랜, 구독 또는 유료 기능을 도입할 수 있습니다.
  2. 회사는 유료 플랜을 도입하거나 무상 제공 범위를 변경하는 경우, 그 내용과 적용일을 적용일로부터 30일 전까지 회사 웹사이트(paldyn.com/branch) 게시와 업데이트 릴리즈 노트로 알립니다.
  3. 베타 기간에 무상으로 제공된 기능의 전부 또는 일부는 베타 종료 후 또는 유료 플랜 도입 시 유료 플랜에서만 제공될 수 있습니다. 회사는 베타 기간에 제공한 기능이나 무상 이용이 계속된다고 보장하지 않습니다.
  4. 이용자가 별도의 유료 이용 조건에 명시적으로 동의하고 결제 절차를 마치지 않는 한, 회사는 이용자에게 요금을 청구하지 않습니다. 유료 플랜에는 이 계약과 함께 별도의 유료 이용 조건이 적용되며, 청약철회 등 관련 법령에 따른 이용자의 권리는 그 조건과 법령에 따릅니다.
  5. 소프트웨어는 소프트웨어에 포함된 Git 또는 이용자가 설정에서 선택한 경우 이용자의 컴퓨터에 설치된 Git을 통해 표준 Git 저장소를 그대로 다룹니다. 따라서 유료 플랜의 도입이나 라이선스의 종료와 관계없이 이용자는 다른 Git 도구로 자신의 저장소를 계속 이용할 수 있습니다.

제5조 (금지 행위)

이용자는 다음 각 호의 행위를 하여서는 안 됩니다.

  1. 정상적인 설치·실행과 이용자 기기의 백업에 필요한 범위를 넘어 소프트웨어를 복제하거나, 소프트웨어를 배포, 재배포, 판매, 대여, 임대, 재허락하거나 공중이 이용할 수 있게 하는 행위
  2. 소프트웨어를 수정, 번역, 개작하거나 소프트웨어의 2차적 저작물을 작성하는 행위
  3. 소프트웨어를 역설계, 디컴파일 또는 디스어셈블하거나 그 밖의 방법으로 소스 코드를 알아내려는 행위. 다만 관련 법령이 이러한 제한에도 불구하고 명시적으로 허용하는 범위에서는 그러하지 아니합니다.
  4. 라이선스 확인, 유료 기능의 제한, 업데이트 서명 검증 등 소프트웨어의 기술적 보호 조치나 라이선스 관리 수단을 우회, 해제 또는 무력화하는 행위
  5. 소프트웨어에 포함된 저작권 표시, 라이선스 고지 또는 상표 표시를 삭제하거나 변경하는 행위
  6. 법령을 위반하거나 제3자의 권리를 침해하는 방법으로 소프트웨어를 사용하는 행위

제6조 (업데이트)

  1. 회사는 업데이트를 제공할 수 있으나, 업데이트를 제공하거나 특정 기능을 유지할 의무를 지지 않습니다.
  2. 소프트웨어에는 업데이트 기능이 내장되어 있으며, 다음과 같이 동작합니다.
    1. 설정의 업데이트 항목에서 "업데이트 자동 확인"이 켜져 있으면(기본값) 소프트웨어를 시작할 때 새 버전이 있는지 확인합니다. 이 설정을 끄면 이용자가 직접 요청할 때만 확인합니다.
    2. 같은 항목에서 "업데이트 자동 다운로드"가 켜져 있으면(기본값) 새 버전을 찾았을 때 이를 백그라운드에서 내려받고 서명을 확인합니다. 이 설정을 끄면 이용자가 다운로드를 선택한 경우에만 내려받습니다.
    3. 업데이트의 설치는 언제나 이용자가 확인한 경우에만 진행되며, 설치를 마치면 소프트웨어가 다시 시작됩니다.
    4. 소프트웨어는 회사의 서명 키로 서명된 업데이트만 설치하며, 서명을 확인할 수 없는 업데이트는 설치하지 않습니다.
  3. 이용자는 내장 업데이트 기능을 통하여 업데이트가 다운로드되고 설치될 수 있음에 동의합니다. 업데이트에는 이 계약이 적용됩니다. 다만 업데이트와 함께 별도의 조건이 제시되는 경우에는 그 조건이 적용됩니다.
  4. 회사는 이전 버전에 대한 지원이나 업데이트 제공을 중단할 수 있습니다.

제7조 (데이터 처리)

  1. 회사는 소프트웨어를 통하여 이용자의 개인정보, 저장소 내용, 파일, 커밋, 자격 증명 또는 사용 기록을 수집하거나 회사의 서버로 전송하지 않습니다. 소프트웨어에는 사용 분석(애널리틱스), 텔레메트리, 광고 또는 충돌 보고 기능이 포함되어 있지 않습니다.
  2. (업데이트와 작성자 사진) 소프트웨어가 이용자의 요청 없이 시작하는 네트워크 통신은 제6조 제2항에 따른 업데이트 확인과 업데이트 자동 다운로드, 그리고 이 항의 끝에 적힌 작성자 사진 요청뿐입니다. 업데이트 확인과 업데이트 다운로드는 HTTPS로만 이루어지며, 회사가 GitHub(github.com, GitHub, Inc. 운영)의 공개 배포 저장소 paldyn/Branch-releases에 게시한 업데이트 정보 파일과 업데이트 파일을 요청합니다. 이 요청에는 소프트웨어가 추가하는 이용자 식별자, 계정 정보 또는 저장소 정보가 포함되지 않습니다. 다만 인터넷 통신의 특성상 이용자의 IP 주소, 요청 시각, 업데이트 모듈의 식별 문자열(User-Agent) 등 일반적인 요청 정보가 GitHub에 전달되며, 이 정보는 GitHub의 개인정보 처리방침에 따라 처리됩니다. 회사는 GitHub가 제공하는 파일별 집계 다운로드 수를 볼 수 있으나, 이 수치로 개별 이용자를 식별할 수는 없습니다. 설정에서 "작성자 사진"이 켜져 있는 동안(기본값은 켜짐) 소프트웨어는 화면에 표시하는 커밋 작성자의 사진을 내장 웹뷰를 통해 HTTPS로 불러옵니다. 작성자 이메일 주소가 GitHub no-reply 주소(번호+이름@users.noreply.github.com)이면 그 주소에 들어 있는 계정 번호만 보내 GitHub(avatars.githubusercontent.com)에서, 그 밖의 작성자 이메일 주소이면 그 이메일 주소의 SHA-256 해시값만 보내 Gravatar(gravatar.com, Automattic Inc. 운영)에서 불러옵니다. 이 요청에는 소프트웨어가 추가하는 다른 정보가 포함되지 않습니다. 다만 해시값이 이메일 주소를 익명으로 만들지는 않습니다. Automattic은 Gravatar에 등록된 주소를 알아볼 수 있고, 주소를 알거나 추측하는 사람은 그 해시값을 계산해 대조할 수 있습니다. 또한 이용자의 IP 주소, 요청 시각, 웹뷰의 식별 문자열(User-Agent)과 언어 설정 등 일반적인 요청 정보가 요청마다 GitHub 또는 Automattic에 전달되어 각 회사의 개인정보 처리방침에 따라 처리되므로, 이 서비스들은 이용자의 연결에서 어떤 커밋 작성자를 보고 있는지 알 수 있습니다. 설정 > 화면에서 "작성자 사진"을 끄면 이 요청은 이루어지지 않습니다.
  3. (Git 원격 작업) 저장소 복제(clone), 페치(fetch), 풀(pull), 푸시(push), 원격 참조 조회(설정 → Git의 연결 점검 포함), 서브모듈 추가와 갱신 등 Git 원격 작업은 이용자가 요청한 경우에만 수행됩니다. 소프트웨어는 Git 프로그램(소프트웨어에 포함된 Git, 또는 이용자가 설정에서 선택하거나 포함된 Git을 실행할 수 없는 경우 이용자의 컴퓨터에 설치된 Git)을 실행하여 이 작업을 처리하며, 이용자가 입력하거나 저장소에 설정된 원격 주소(서브모듈 주소를 포함합니다)에만 연결합니다. 허용되는 전송 방식은 file, https, http, ssh, git입니다. 인증은 이용자의 Git 설정, SSH 키와 자격 증명 도우미가 처리하며, 소프트웨어 자체는 비밀번호나 토큰 등 자격 증명을 저장하지 않습니다. 포함된 Git을 사용하는 경우에는 소프트웨어에 포함된 Git의 macOS 키체인 자격 증명 도우미가 기본으로 설정됩니다(이용자의 Git 설정으로 바꿀 수 있습니다). 이 도우미는 Apple의 Git에 포함된 도우미와 마찬가지로 Git이 인증에 성공한 HTTPS 자격 증명을 이용자 컴퓨터의 로그인 키체인에 저장하고 그곳에서 읽어 오며, 이 자격 증명은 회사에 전송되지 않습니다. 다만 이용자가 원격 주소에 자격 증명을 포함하여 입력하면 Git이 그 주소를 저장소 설정에 기록할 수 있습니다. 원격 서비스(예: GitHub, GitLab, Bitbucket, Azure DevOps)와 주고받는 정보에는 해당 서비스의 약관과 개인정보 처리방침이 적용됩니다. Git 훅, 부분 복제(partial clone) 저장소의 자동 객체 내려받기 등 이용자의 Git 설정이나 저장소 설정에 따른 Git의 동작은 그 설정대로 이루어집니다. 소프트웨어는 화면을 최신 상태로 유지하기 위해 주기적으로 저장소 상태를 다시 읽지만, 이때 페치(fetch) 등 원격 저장소에 연결하는 Git 명령은 실행하지 않습니다.
  4. (이용자 기기에 저장되는 정보) 소프트웨어는 다음 정보를 이용자의 기기에만 저장하며 회사로 전송하지 않습니다.
    1. 설정(테마, 강조 색상, 언어, 단축키, 업데이트 설정, 외부 편집기 선택(앱 이름 또는 이용자가 지정한 앱의 경로) 등), 작업 공간 정보(열어 둔 저장소의 로컬 경로, 탭, 그룹), 설치하기 직전에 기록하는 업데이트의 버전과 릴리즈 노트(다시 시작한 뒤 릴리즈 노트를 보여 주는 데 쓰며, 임시 기록은 보여 주었거나 더 필요하지 않게 되면 지웁니다), 설정에서 다시 볼 수 있도록 자동 표시 설정과 관계없이 보관하는 최근 설치 버전의 릴리즈 노트(새로 설치한 버전의 노트로 대체하며 백업에는 포함하지 않습니다), 저장소별로 작성 중인 커밋 메시지 초안, 화면 배치, 특정 커밋을 체크아웃한 뒤 되돌아갈 브랜치의 이름과 분리된 HEAD(detached HEAD)가 시작된 커밋 ID: 소프트웨어에 내장된 웹뷰의 로컬 저장소(macOS의 경우 ~/Library/WebKit/com.paldyn.branch/)
    2. 창의 위치와 크기, 사용할 Git의 선택, 포함된 Git을 위해 생성한 시스템 수준 Git 설정: 애플리케이션 설정 폴더의 .window-state.json, git-executable.json, bundled-git/gitconfig(macOS의 경우 ~/Library/Application Support/com.paldyn.branch/)
    3. Git 작성자 이름과 이메일: 이용자가 설정 화면에서 저장한 경우에만 이용자의 Git 설정(전역 설정 또는 해당 저장소 설정)에 기록
    4. 대화형 리베이스에 필요한 임시 작업 파일: 해당 저장소의 .git 폴더 안
    5. 복구용 참조: 소프트웨어는 리셋(reset), 리베이스(rebase), 대화형 리베이스를 하기 전에 HEAD가 가리키는 커밋을 기록하고, 원격 저장소의 브랜치나 태그를 삭제하기 전에 그 원격 브랜치나 태그가 가리키는 커밋이나 태그를 먼저 페치합니다. 강제 푸시 전에는 덮어쓸 것으로 확인한 원격 커밋을 기록합니다. 이전 상태를 복구할 수 있도록 이들을 각각 해당 저장소의 refs/branch/recovery/ 아래에 Git 참조로 reflog 기록과 함께 보관합니다. 새 복구 지점이 만들어지면 소프트웨어가 만든 것으로 확인할 수 있는 참조 중 최신 20개 또는 생성 후 14일 미만인 참조를 보존하고, 두 조건에 모두 해당하지 않는 오래된 참조는 자동 정리 대상이 됩니다. 진행 중인 세션이 사용하는 참조와 소프트웨어가 만든 것으로 확인할 수 없는 참조는 자동으로 삭제하지 않으며, 저장소의 워크트리 중 하나라도 세션 정보를 읽을 수 없으면 자동 정리를 건너뜁니다. 따라서 일부 참조는 더 오래 남을 수 있습니다. 이용자는 git update-ref -d <참조 이름>으로 하나씩, 또는 git for-each-ref --format='delete %(refname)' refs/branch/recovery/ | git update-ref --stdin으로 한꺼번에 직접 삭제할 수도 있습니다. 이 참조가 남아 있는 동안에는 리셋 등으로 브랜치에서 제외된 커밋이라도 Git의 가비지 컬렉션(garbage collection)이 그 커밋을 삭제하지 않습니다. 일반적인 푸시(push)와 복제(clone)에서는 이 참조가 전송되지 않지만, git push --mirror나 git clone --mirror처럼 저장소의 모든 참조를 복사하는 명령에서는 함께 전송됩니다.
    6. 이전 버전의 식별자로 저장된 설정이 있는 경우, 소프트웨어는 처음 실행할 때 이를 기기 안에서 새 위치로 복사합니다.
    7. 제2항에 따라 불러온 작성자 사진과 그 주소(이메일 해시값 또는 GitHub 계정 번호가 들어 있음): 내장 웹뷰의 캐시인 ~/Library/Caches/com.paldyn.branch/(macOS의 경우). "작성자 사진"을 끈 뒤에도 남아 있을 수 있습니다.

    이 정보는 소프트웨어를 삭제한 뒤에도 기기에 남을 수 있으며, 이용자는 위 위치의 파일과 제5호의 복구용 참조를 직접 삭제할 수 있습니다.

  5. (기기 안의 기타 연동) 소프트웨어는 이용자가 요청한 경우에 Finder, 터미널 또는 이용자가 설정 → 외부 앱에서 선택한 외부 편집기(따로 선택하지 않으면 Visual Studio Code)에서 저장소를 열고, 기본 브라우저에서 공식 릴리즈 노트 페이지를 열고, 클립보드에 텍스트를 복사하며, 파일 선택 대화상자를 엽니다. 이미지 미리보기 등 저장소 내용의 표시는 모두 이용자의 기기 안에서 처리됩니다.
  6. 회사가 유료 플랜의 라이선스 확인 등을 위하여 이 조에 적힌 것과 다르게 정보를 처리하려는 경우, 시행 전에 이 계약을 변경하여 회사 웹사이트(paldyn.com/branch) 게시와 업데이트 릴리즈 노트로 알리고, 관련 법령상 필요한 경우 이용자의 동의를 받습니다.

제8조 (소유권)

  1. 소프트웨어는 판매되는 것이 아니라 이용이 허락되는 것입니다. 소프트웨어와 그 복제물 및 업데이트에 관한 저작권, 특허권, 상표권, 영업비밀 등 모든 지식재산권은 회사 또는 회사에 라이선스를 부여한 자에게 귀속됩니다.
  2. 이용자가 소프트웨어로 다루는 저장소, 파일, 커밋 등의 콘텐츠에 대한 권리는 이용자 또는 정당한 권리자에게 있으며, 회사는 이 계약에 따라 그 콘텐츠에 대한 어떠한 권리도 취득하지 않습니다.

제9조 (피드백)

  1. 이용자는 피드백을 제공할 의무가 없습니다.
  2. 이용자가 피드백을 제공하는 경우, 회사는 이용자에게 대가를 지급하거나 출처를 표시하지 않고 피드백을 소프트웨어와 회사의 제품 및 서비스에 자유롭게 이용, 수정, 공개 및 상업화할 수 있는 전 세계적이고 영구적이며 취소할 수 없는 무상의 권리를 가집니다.
  3. 피드백에는 비밀 정보나 제3자의 권리가 있는 내용을 포함하지 마십시오. 회사는 피드백에 대하여 비밀유지 의무를 지지 않습니다. 다만 피드백과 함께 제공된 개인정보는 관련 법령에 따라 처리합니다.

제10조 (제3자 구성요소와 서비스)

  1. 소프트웨어에는 제3자 구성요소가 포함되어 있으며, 그 목록과 라이선스 전문은 소프트웨어와 함께 제공되는 THIRD_PARTY_NOTICES.md에 있습니다. 소프트웨어에 포함된 Git 프로그램의 경우 THIRD_PARTY_NOTICES.md는 그 프로그램과 함께 제공되는 라이선스 전문과 소스 코드 제공 안내의 위치(macOS 앱의 Contents/Resources/git/share/doc/branch-bundled-git/)를 안내합니다. 제3자 구성요소에는 해당 라이선스가 적용되며, 제5조를 포함한 이 계약의 어떠한 조항도 그 라이선스에 따라 이용자가 가지는 권리를 제한하지 않습니다.
  2. GitHub 등 제3자가 운영하는 서비스의 이용에는 해당 제3자의 약관이 적용됩니다. 회사는 제3자 서비스의 가용성, 내용 또는 정보 처리에 대하여 책임을 지지 않습니다.
  3. 소프트웨어에 표시되는 GitHub, GitLab, Bitbucket, Azure DevOps의 명칭과 로고는 각 권리자의 상표이며, 원격 저장소를 호스팅하는 서비스를 구별하기 위해서만 사용됩니다. 이는 권리자와의 제휴, 후원 또는 보증을 의미하지 않습니다.

제11조 (베타 소프트웨어 및 보증의 부인)

  1. 소프트웨어는 베타 버전으로서 오류, 결함 또는 기능 누락이 있을 수 있으며 예고 없이 변경될 수 있습니다.
  2. 소프트웨어는 "있는 그대로(AS IS)" 그리고 "이용 가능한 상태로(AS AVAILABLE)" 제공됩니다. 관련 법령이 허용하는 최대 범위에서, 회사는 상품성, 특정 목적에의 적합성, 권리 비침해, 정확성 및 중단 없는 작동에 관한 보증을 포함하여 명시적이거나 묵시적인 어떠한 보증도 하지 않습니다.
  3. 리셋(reset), 변경 사항 버리기(discard), 리베이스(rebase), 브랜치나 태그의 삭제 등 일부 Git 작업은 되돌릴 수 없을 수 있습니다. 이용자는 중요한 데이터를 정기적으로 백업하여야 합니다.
  4. 이 조는 관련 법령에 따라 배제하거나 제한할 수 없는 이용자의 권리에는 적용되지 않습니다. 이 조의 내용 중 「약관의 규제에 관한 법률」 등 관련 법령에 따라 효력이 없는 부분은 적용되지 않으며, 그 부분은 관련 법령에 따릅니다.
