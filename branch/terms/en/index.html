7. Data practices

  1. PALDYN does not use the Software to collect your personal information, repository contents, files, commits, credentials or usage history, or to send them to PALDYN's servers. The Software contains no usage analytics, telemetry, advertising or crash reporting.
  2. Updates and author photos. The only network communications that the Software starts without your request are the update check and the automatic update download described in Section 6.2 and the author photo requests described at the end of this paragraph. Update checks and update downloads use HTTPS only and request the update information file and update files that PALDYN publishes in its public paldyn/Branch-releases repository on GitHub (github.com, operated by GitHub, Inc.). These requests contain no user identifier, account information or repository information added by the Software. As with any internet request, however, ordinary request information such as your IP address, the time of the request and the updater's identification string (User-Agent) reaches GitHub and is handled under GitHub's privacy statement. PALDYN can see the aggregate download count of each file that GitHub provides, which does not identify individual users. While "Author photos" is turned on in the settings (it is on by default), the Software loads, over HTTPS through its built-in web view, the photo of each commit author it shows: when the author's email address is a GitHub no-reply address (number+name@users.noreply.github.com), from GitHub (avatars.githubusercontent.com), sending only the account number in that address; for any other author email address, from Gravatar (gravatar.com, operated by Automattic Inc.), sending only the SHA-256 hash of that email address. These requests contain nothing else added by the Software. The hash does not make the email address anonymous, however: Automattic can recognize addresses registered with Gravatar, and anyone who knows or guesses an address can compute its hash and match it. Ordinary request information, such as your IP address, the time of the request, and the web view's identification string (User-Agent) and language preferences, reaches GitHub or Automattic with each request and is handled under their privacy statements, so these services can tell which commit authors are being viewed from your connection. Turning off "Author photos" in Settings → Appearance stops these requests.
  3. Git remote operations. Git remote operations, such as cloning, fetching, pulling, pushing, listing remote references (including the connection check in Settings → Git) and adding or updating submodules, run only when you request them. The Software performs them by running a Git program (the Git included with the Software or, if you choose it in the settings or the included Git cannot run, the Git installed on your computer) and connects only to remote addresses that you enter or that are configured in the repository, including submodule addresses. The permitted transports are file, https, http, ssh and git. Authentication is handled by your Git configuration, SSH keys and credential helpers; the Software itself does not store passwords, tokens or other credentials. When the included Git is used, the macOS keychain credential helper of Git that is included with the Software is configured by default (your Git configuration can replace it). Like the helper of Apple's Git, it stores the HTTPS credentials with which Git has signed in successfully in the login keychain on your computer and reads them from there; they are not sent to PALDYN. If you include credentials in a remote address, however, Git may record that address in the repository configuration. Information exchanged with a remote service (for example GitHub, GitLab, Bitbucket or Azure DevOps) is subject to that service's terms and privacy statement. Git behaves as your Git and repository configuration directs, for example when running Git hooks or when Git automatically downloads missing objects in a partial clone. The Software periodically re-reads repository status to keep its display current, but it does not run Git commands that contact remote repositories, such as fetch, for this purpose.
  4. Information stored on your device. The Software stores the following information only on your device and does not send it to PALDYN:
    1. settings (such as theme, accent color, language, keyboard shortcuts, the update settings and the external editor you chose, which is an application name or the path of an application you selected), workspace information (local paths of the repositories you opened, tabs and groups), the version and release notes of an Update recorded right before it is installed (used to show release notes after the restart; this temporary entry is deleted once shown or no longer needed), the most recently installed version's release notes retained for reopening in Settings regardless of the automatic-popup setting (replaced by the next installed version's notes and excluded from backups), and, for each repository, commit message drafts in progress, layout, the name of the branch to return to after you check out a specific commit, and the commit ID at which a detached HEAD began: in the local storage of the Software's built-in web view (on macOS, ~/Library/WebKit/com.paldyn.branch/);
    2. window position and size, the choice of Git executable and the system-level Git configuration generated for the included Git: in .window-state.json, git-executable.json and bundled-git/gitconfig in the application settings folder (on macOS, ~/Library/Application Support/com.paldyn.branch/);
    3. Git author name and email: written to your Git configuration (global or for the repository) only when you save them in the settings;
    4. temporary working files needed for an interactive rebase: inside that repository's .git folder;
    5. recovery references: before a reset, a rebase or an interactive rebase, the Software records the commit that HEAD points to, and before it deletes a branch or tag in a remote repository, it first fetches the commit or tag that the remote branch or tag points to. Before a force push, it records the remote commit confirmed for replacement. It keeps each of these in that repository as a Git reference under refs/branch/recovery/, with a reflog entry, so that the previous state can be recovered. When a new checkpoint is created, the Software keeps the newest 20 references it can identify as its own or those created less than 14 days ago; older references that satisfy neither condition are eligible for automatic cleanup. It does not automatically delete references used by active sessions or references it cannot identify as created by the Software, and it skips cleanup if it cannot read session information from any worktree of the repository. Some references may therefore remain longer. You can also delete them yourself, for example with git update-ref -d <reference name>, or all at once with git for-each-ref --format='delete %(refname)' refs/branch/recovery/ | git update-ref --stdin. While they remain, Git's garbage collection does not remove the commits they point to, even after a reset has removed those commits from your branches. Ordinary pushes and clones do not transfer these references, but commands that copy every reference of a repository, such as git push --mirror or git clone --mirror, do; and
    6. if settings saved under the identifier of an earlier version exist, the Software copies them to the new location on your device the first time it runs;
    7. author photos loaded under paragraph 2 and their addresses, which contain the email hashes or GitHub account numbers: in the built-in web view's cache in ~/Library/Caches/com.paldyn.branch/ (on macOS). They can remain there after you turn off "Author photos".

    This information may remain on your device after you delete the Software. You can delete the files in the locations above, and the recovery references in item 5, yourself.

  5. Other local integrations. When you ask it to, the Software opens a repository in Finder, Terminal or the external editor you choose in Settings → External apps (Visual Studio Code unless you choose another application), opens the official release notes page in your default browser, copies text to the clipboard and opens file selection dialogs. Previews of repository contents, such as image previews, are processed entirely on your device.
